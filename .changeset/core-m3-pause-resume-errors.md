M3: pause, resume and failure handling. New methods `pause()`/`resume()`, `pauseFolder(path)`/`resumeFolder(path)`, `pauseFile(file | id)`/`resumeFile(file | id)` (`pauseMode: 'abort' | 'finishChunk'`; a paused file gives up its slot and resumes with only the missing chunks), `cancelFolder(path)`, `retryFailedOnly(folderPath?)` (returns the count), `retryFile(file | id)` and `clearPersistedState()`. Resume after a reload: acknowledged chunks and finished files are saved in IndexedDB (`persistState`, `persistKey`, 7-day expiry, memory fallback with one warning), finished files are skipped with `success(file, { skipped: true, uploadId })`, `chunkStatusUrl` is asked only for files being resumed, and with `transformFile` only files whose blob actually changed lose chunk-level resume. Lifecycle: `offline` pauses and `online` resumes (`autoResumeOnReconnect`), `pagehide` pauses, a network failure while the page is hidden pauses instead of using up retries (`autoPauseOnHidden`). Events `paused`, `resumed`, `offline`, `online` are now emitted. Protected hooks `_addFormElementData(formData)` and `_completeExternal(file)` for subclasses; `upload.chunkSize`; `DataBlock` type.

Fixes from the M2 review (decision 0013, protocol v1.2): `uploadMultiple` groups queued files across batches and sends `adSessionId[i]` per file; `queuecomplete` fires at most once per run; a throw while a request is built fails the file with the new code `REQUEST_SETUP_FAILED` instead of stalling it; an abort core did not start counts as `NETWORK`; a chunk-status `404` no longer lets chunks of the old uploadId land; the chunk size is fixed per file; `url`/`method` functions receive `(files, dataBlocks)` and `timeout` may be a function; `setOption('url')` starts a waiting queue; `sendManifest` without `manifestUrl` warns once; a `renameFile()` result with a separator is rejected (`INVALID_PATH`); `disable()` cancels queued files first; `removeAllFiles()` also removes folders left without files.
