Bad connections (backend contract v1.3 and v1.4). New options `stallTimeout` (default 30 s, `null` = off: a request with no upload progress is aborted and retried as the new error code `STALLED`) and `connectivityProbeUrl` (optional `HEAD` endpoint used to check the server while it cannot be reached). New methods `reconnect()` ("Retry now") and `getConnectionState()` (returns the new exported `ConnectionState` type: `{ state: 'online' | 'offline' | 'unreachable', attempt, retryAt }`), and the new event `reconnecting(attempt, delayMs)`. `PauseReason` gains `'unreachable'`: when the browser says it is online but three requests in a row get no HTTP response, the upload pauses instead of using up retries, probes with growing delays and resumes by itself when the server answers. Uploads also pause while the manifest, chunk-status or finalize request cannot get through, and when started offline, instead of failing the batch. When a chunk-status `404` gives a file a new uploadId, the whole batch manifest is sent again with it (backends should accept a repeated manifest for the same `sessionId`, latest wins, and may reject uploadIds that are not in it). Backends should also check chunk byte lengths and answer `400 INVALID_CHUNK` for a mismatch. The full contract is published in `docs/protocol.md`.
